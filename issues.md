# Static Code Analysis Issues Report

| Issue | Type | Line(s) | Description | Fix Approach |
|---|---|---:|---|---|
| Unsafe pickle backup and restore | Security - Medium | 2, 42-49 | The starter code imported `pickle`, wrote orders to `orders.pkl`, and loaded them with `pickle.load`. Bandit flagged this because untrusted pickle data can execute code during deserialization. | Replaced pickle storage with JSON backup and restore using `json.dump` and `json.load`, then validated restored order data before accepting it. |
| Mutable default argument | Code Quality - Medium | 11 | `create_order` used `order_history=[]`, which creates one shared list reused across calls. Pylint flagged this as a dangerous default value. | Changed the default to `None` and created a new list inside the function when no history is passed. |
| Unknown menu items silently accepted | Logic Bug - Medium | 14-15, 59 | The starter code used `menu.get(i, 99)`, so invalid dishes such as `sushi` were accepted with a fake price. | Validated each item against the loaded menu and raised `ValueError` for unknown menu items. |
| Broad exception handling hid failures | Reliability - Medium | 22-25, 29-33 | `update_order_status` swallowed every exception, and menu loading caught all exceptions without validating the loaded menu. This hid invalid order IDs, invalid statuses, and file/parsing problems. | Replaced broad exception handling with explicit validation and specific exceptions for file loading, JSON parsing, and invalid menu data. |
| Invalid order statuses accepted | Logic Bug - Medium | 9, 21-25, 62 | The starter code allowed any status string, including `teleported`, to be written to an order. That corrupted backups and revenue/state reporting. | Checked statuses against `VALID_STATUSES` before updating an order and raised `ValueError` for invalid statuses. |
| Empty customer and empty order accepted | Input Validation - Medium | 11, 60 | The starter code allowed an empty customer name and an empty item list, creating unrealistic orders with bad data. | Added customer-name and item-list validation in `create_order` and restore validation. |
| Backup restore did not update next ID | Logic Bug - Medium | 47-49 | Restoring orders replaced the order dictionary but did not update `next_id`, so a later order could reuse an existing ID. | After restore, set the next ID to one greater than the largest restored order ID. |
| Naming and formatting issues | Code Quality - Low | 1, 16, 51, 70 | The starter code had long lines, missing docstrings, direct script execution on import, and a non-snake-case function name `printQueue`. | Added docstrings, formatted the file for Flake8, renamed `printQueue` to `print_queue`, and guarded execution with `if __name__ == "__main__":`. |
